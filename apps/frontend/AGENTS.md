# 前端项目规则

本项目同时遵守仓库根目录的 [AGENTS.md](../../AGENTS.md)。阅读 [README.md](README.md) 和 [架构方案](../../docs/architecture-frontend-desktop.md) 后修改代码。

1. View 组合本功能组件，状态和用例逻辑留在所属 feature；不要把拆出的状态重新集中到根 `App`。
2. 功能组件优先留在所属 feature，确实跨功能复用时才进入 `shared`。
3. 不直接导入 `@tauri-apps/*`、Rust 实现或桌面项目内部模块。宿主能力通过 `@hermess/contracts` 的接口注入。修改能力方法或 DTO 时，先追踪 React 调用、契约定义、桌面适配层和 Rust 接收方，再同步修改并验证；不能只凭 TypeScript 类型检查判定跨层行为正确。
4. 浏览器预览中的模拟数据只用于界面开发；报告验证结果时与桌面构建和原生窗口操作分开。
5. 修改前端代码至少运行 `pnpm --dir apps/frontend typecheck` 与 `pnpm build`。新增代码和文档使用 UTF-8。
6. 前端测试放在项目的 `tests/`，不要在 `src/` 中新增测试文件；测试数据由测试代码构造。浏览器预览源码属于可复现的开发工具，不放机器专属配置或凭据。
7. 修改功能流程或状态时，检查本次涉及的入口、恢复、失败、重试和切换路径；测试覆盖改变后的可观察行为及可能受影响的现有路径。修改后端参数的传递或展示时，核对 [锁定上游](../../runtime/upstream.lock.json)、契约与 Rust 请求构造，并按根规则完成接收方验证。浏览器预览的模拟成功不代表后端或原生窗口成功。
