# 桌面客户端项目规则

本项目同时遵守仓库根目录的 [AGENTS.md](../../AGENTS.md)。阅读 [README.md](README.md)、[架构方案](../../docs/architecture-frontend-desktop.md) 和 [运行时决策记录](../../docs/ADR-0001-runtime-and-process.md) 后修改代码。

1. 自有 Hermes 实例的锁、子进程、令牌、端口与 Gateway 连接由同一个运行时所有者控制；不得扫描端口接管外部实例。
2. Tauri TypeScript 只负责能力接口的宿主实现和生产装配，不承接页面 JSX 或聊天状态逻辑。
3. Rust `main.rs` 只负责初始化、状态注入和命令注册；功能实现放在所属模块，不把新逻辑继续堆进单个大文件。
4. 保持固定上游协议与发布资源路径；修改命令、事件或 Gateway 请求格式前核对锁定 fork 的接收方实现，同步修改共享契约和实际覆盖该请求的验证。`src-tauri/` 还须遵守 [Rust 规则](src-tauri/AGENTS.md)。
5. 按改动范围运行前端构建、Rust 格式、编译、测试及 Gateway 冒烟；先核对冒烟脚本与当前生产请求一致，脚本仅验证自身构造的请求。接口改动必须额外验证目标接收方的接受或拒绝行为；原生窗口与安装包分别验收。新增代码和文档使用 UTF-8。
6. `runtime` 子模块使用显式导入，避免通过 `use super::*` 隐式依赖父模块的导入；资源安装和存储定位逻辑分别归 `payload.rs` 与 `location.rs`，进程及 Gateway 生命周期仍由 `mod.rs` 统一持有。
7. Rust 单元测试放在独立的 `tests/` 文件中，生产模块仅用 `#[cfg(test)]` 声明测试模块；不要把测试实现或机器专属路径写入生产源码。测试仍须覆盖私有实现时保留单元测试模块，不为移动文件而扩大生产接口的可见性。
8. 所有由桌面客户端触发的环境、工具、版本及依赖探测必须在后台无窗口运行；页面打开、自动刷新、手动刷新，以及探测失败或超时，都不得弹出或闪现终端窗口。Windows 上启动探测子进程时设置 `CREATE_NO_WINDOW`（`0x0800_0000`）或等效标志，不通过可见的终端或 Shell 执行探测；新增探测路径须核对这一点。
9. 桌面客户端新增的产品自有进程及其后代必须由 `process_manager` 启动并登记，包括网关、浏览器 CDP、PTY 终端、工具安装和短时探测。启动、失败、超时、正常结束时均须释放登记；托盘退出先禁止新启动，再依次停止终端、浏览器、临时任务和网关，最后退出后台。Windows 进程组句柄必须覆盖子进程树，并在后台异常退出时由系统关闭。系统默认浏览器和文件管理器属于交给用户系统处理的外部应用，不得按本产品进程清理。新增进程入口须同步更新架构检查和生命周期验证。
