# Windows 工具环境与首次自动安装方案

日期：2026-11-08。状态：按最新要求修订，尚未实施；优先验证客户端适配，是否需要 fork 变更尚待核实，未获修改 fork 的批准。macOS 保持现状。

## 已确认目标

- Windows 用户任务优先使用用户已有的可用工具或项目环境，包括 Python、Node、npm、Git 和 GitHub CLI（`gh`）；缺失时使用独立 PM 工具；两者都缺失则提示按名称安装，不回退到产品内置 runtime。
- PM 的工具目录位于安装目录下独立的 `tools`，所有 Profile 共用；与安装包自带的 `runtime/payload` 分开。
- 首次自动安装直接执行不带名称的 `hermes pm install`，依照锁定 PM 的默认集合准备工具并同步 Hermes Python 依赖；用户项目依赖仍放项目独立环境。
- Windows 安装后的首次启动，在存储位置确定、产品运行时就绪后触发安装，独立 PM 目录供全部 Profile 共用。当前 Windows 默认集合包含 Python、Node、npm、uv、FFmpeg、ripgrep 和 Hermes venv，并尝试安装未被跳过的默认可选组件 agent-browser、Chromium、cua-driver；不代表安装 PM 目录中的全部可选包，Git、gh、本地模型后端等仍按需处理。
- 自动准备 PM 工具副本与用户任务的工具选择是两件事：首装准备 PM 默认集合；执行用户任务时继续优先使用用户已有环境。
- “工具与能力”展示用户已有工具及 PM 管理工具，说明实际来源；内置后台 runtime 不作为用户任务的可用环境，也不冒充独立 PM 用户工具已经安装。

## 当前代码证据

锁定 fork：`882037eb8745b505db438217513c4c94f95c93c1`，官方基线 `v0.22.5`，以 `runtime/upstream.lock.json` 为准。

1. `apps/desktop/src-tauri/src/runtime/downloadable_tools.rs` 已按白名单执行 `hermes pm install NAME`，但缺少 Python 和 uv；安装状态同时检查内置 payload 与数据目录，不能直接用于独立用户工具目录的判定。
2. `apps/desktop/src-tauri/src/diagnostics.rs::probe_local_tools` 当前探测系统 Python、Node、npm、Git、FFmpeg、FFprobe、ripgrep、uv 和 gh。
3. `apps/frontend/src/features/tools/mergeLocalTools.ts` 将内置资源、PM 目录和系统探测合并；`LocalToolCard.tsx` 优先将内置资源作为可用状态，并会隐藏对应下载按钮。
4. `upstream/hermes-agent/pm/environments.py::store_root` 支持 `HERMES_RUNTIME_DIR`；但这是工具存储入口，不等于终端环境隔离开关。
5. `upstream/hermes-agent/pm/user_facing.py::user_facing_path` 明确将 PM 工具放在用户工具之后。`tools/environments/local.py::_make_run_env` 还接入会话客户端工具链，调用 `_user_tools_first` 重排 PATH。
6. `tools/environments/base.py::init_session` 调用 `login=True`；`local.py::_run_bash` 以 `bash -l -c` 初始化，可加载用户登录配置。按最新要求保留用户环境加载，但需验证终端最终解析不会回退到内置 runtime；只检查桌面启动 PATH 不足以证明这一点。
7. Windows 安装脚本 `apps/desktop/src-tauri/nsis/installer-runtime.nsi` 整体切换 payload，因此后下载工具不能写入 payload 目录并依赖其跨升级保留。
8. `pm/cli.py::_live_progress` 在非终端管道模式仍输出工具名称、下载百分比和字节数（约每 4 MiB 一次）及解包状态；总长度未知时不会输出百分比。当前桌面安装器将 stdout/stderr 写入日志并等待命令结束，前端只有单项 `installingTool`，还没有下载进度契约或后台任务状态回读。

## 拟实施范围

### 客户端

- 统一解析安装目录下的共享 `tools`，开发态使用仓库忽略目录；安装、状态检查与执行读取同一目录，不写入机器绝对路径到源码。
- Windows 保留用户工具探测，排除产品内部 runtime 路径；用户环境不因与产品锁定版本不同就直接判定缺失，工具兼容要求按实际调用核实。原有 macOS 探测保持不变。
- PM 卡片展示默认安装结果及其他可选组件；未包含在默认集合中的工具仍可按名称安装。
- 明确区分独立 PM 工具安装状态与内置 runtime。安装完成回读工具事实；失败保留错误和重试入口，不因存在内置版本显示成功。
- 用户任务保持用户工具优先、独立 PM 工具其次；缺失时不从内置 runtime 兜底。产品内部启动、依赖管理和内置能力可以继续使用其内部 runtime，不因用户工具版本变化而改变内部解释器。
- 安装目录不可写时明确失败；升级保留独立工具目录，明确卸载行为。已有数据目录工具迁移另行核对，未验证前不删除旧目录。

### 自动安装与界面进度

- 自动触发属于安装后的首次应用启动，不在 NSIS 中执行联网下载。应用有可用界面后展示准备状态，macOS 不启用这条自动流程。
- 复用同一个受进程管理器登记的后台安装任务，以参数列表传递 `pm install`；默认工具、依赖同步和默认可选组件遵循锁定 PM 的安装顺序，不额外并行启动多个安装命令。
- 任务由桌面后台持有，切换设置页、Profile 或刷新状态不创建重复任务。后续启动检查独立 PM 工具事实，全部有效时不重复安装；未完成或失败时显示剩余状态与重试入口。
- 展示当前工具、版本、下载字节、已知总量时的百分比，以及准备、下载、解包、验证和最终结果。当前 CLI 不提供的阶段细节不凭时间推算；未输出总量时使用不定进度。
- 下载 100% 后进入解包/检查，只有命令成功并且默认必需工具及 Hermes 依赖状态回读通过才显示准备完成。默认可选组件下载失败可能只警告、不影响 PM 退出码，须单独显示缺失和重试入口，不能将退出码零写成全部组件安装成功。失败区分当前工具、退出失败、超时、目录不可写，提供可审查的脱敏错误摘要。
- 安装日志按操作标识关联开始、阶段变化、最终结果与清理；不向界面直接转发未经筛选的命令输出或敏感环境。
- 关闭窗口收起到托盘时可继续；退出后台时回收产品安装进程树，未完成任务在下次启动重新检查。重试和重启后的复用能力以 PM 实际支持为准，不承诺未经验证的断点续传。

### 适配边界与可能的 fork 接口

- 当前内核的用户工具优先规则与最新需求一致，不再需要为了排除用户工具链而改动它。
- 先验证独立工具目录配置与用户任务环境构造能否在客户端适配层完成；验证终端和后台任务最终 PATH 均不引入内置 runtime，保留用户登录配置、项目环境及必要系统命令。
- 只有确认客户端无法排除内置 runtime 回退时，才提出 Windows 产品宿主显式开启的最小接口，并附真实调用证据与影响范围，取得明确批准后修改 fork；默认关闭，原 CLI 和 macOS 行为保持原样。
- PM 路径覆盖、工具安装检查、用户工具执行与内部解释器启动边界需分别验证；不通过替换锁定源码、构建补丁、Python monkeypatch 或全局修改用户环境实现。
- 获批后从维护分支建立独立开发分支，经独立审核和 PR 合回；产品最后更新锁文件，不直接修改忽略的锁定检出或合入维护分支。

## 验证要求

- 在构造的用户 PATH 放置可识别的 Python/Node/npm/FFmpeg；向真实工具入口提交命令，验证优先执行用户工具；用户任务本身不额外触发下载，默认集合首次自动安装单独验证。
- 用户工具缺失、独立 PM 工具存在时应命中独立 PM 目录；用户工具和独立 PM 工具都缺失而内置 runtime 存在时应提示缺失，不能执行内置解释器。指定安装后命中独立目录。
- Git、gh 命中允许的系统路径；命名 Profile 与默认 Profile 命中同一 PM 工具目录。
- 包含中文和空格的安装路径、无写权限、失败重试、应用重启、升级保留及安装日志脱敏。
- 默认集合首次自动安装、已有安装跳过、工具依赖顺序、Hermes 依赖同步、默认可选组件失败或曾被跳过、总量未知、下载完成后的解包/验证、失败重试，以及切页/切 Profile 不重复执行；验证实际 UI 状态与后端命令输出、工具事实一致。
- 终端首次初始化、后台命令、会话恢复、Shell 登录配置及客户端工具链注入均需覆盖；系统 Shell/基本命令不能被误伤。
- 这项策略控制默认工具解析，不等于文件系统沙箱；本机自由终端仍可能通过绝对路径主动执行其他程序，不能宣称已经阻止全部任意路径执行。
- 按仓库规则执行构建、Rust 和契约检查，验证锁定接收方实际行为；macOS 运行时策略保持不变，并说明未进行的原生验收。

本轮只完成代码追踪和方案整理，没有修改工具行为或执行安装。
