### Windows 沙箱事实

固定版本的 unelevated restricted-token 沙箱明确拒绝 deny-read，不能通过仅过滤环境变量来宣称工具读不到文件。当前使用 MXC；本机正常用户环境已验证实际写项目文件和拒绝读取测试 vault。MXC 缓存用产品会话内的独立 `LOCALAPPDATA`，避免默认落入个人工具缓存；App Server 的 `CODEX_HOME`、`CODEX_SQLITE_HOME`、数据库与日志目录也独立。

当前不会退回无隔离模式。MXC 不可用时任务失败。可能绕过沙箱的命令执行/写文件/权限扩展审批统一拒绝，不能把旧草稿的“允许一次”界面能力写成已验收的安全提权。主密钥自动解锁也不防护同一操作系统用户下的恶意宿主程序。

## 2026-11-08 四项会话命令

本轮范围限于聊天、共享契约和运行时适配，不扩改设置模块。所有参数从原聊天输入框填写，命令提示、目标状态、澄清问题和执行结果留在聊天内，不使用弹窗。

| 输入 | 实际行为 |
| --- | --- |
| `/goal 目标与验收条件` | 设置并启动原生持续目标；可显式添加 `--budget 50000`，省略时不新增预算，已有预算按原生语义保留 |
| `/goal`、`/goal pause`、`/goal resume`、`/goal clear` | 查询、暂停、恢复、清除当前线程目标；运行中也可使用聊天目标卡中的对应操作 |
| `/plan`、`/plan 任务`、`/plan off` | 保存计划模式、在计划模式发起本轮任务、恢复执行模式；模式随实际请求发送 |
| `/compact` | 调用 Codex 原生上下文压缩 |
| `/review` | 原生审查未提交改动 |
| `/review --base main`、`/review --commit <SHA>`、`/review --custom 审查要求` | 原生审查基准分支、指定提交或自定义范围 |

调用路径为 `ProgrammingInput` → `programmingCommands` 参数解析 → `useProgrammingController.executeCommand` → `CodingApi.command` → 桌面 Tauri 适配 → `coding_session_request` → 既有共享进程管理器下的编程 Worker。命令参数在 Rust 边界重新验证；目标和澄清问题通过会话快照展示。计划模式用于先分析与澄清，启动或恢复持续目标前须显式切回执行模式。

Worker 使用锁定 App Server 的 `thread/goal/set|get|clear`、`thread/settings/update`、`review/start` 和 `thread/compact/start`。目标由原生引擎自动续跑，不发送额外“继续”消息，不为目标添加客户端 30 分钟上限。收到目标完成状态后仍处理剩余轮次事件，并检查原生线程空闲，避免丢失最终回答。目标查询、暂停和清除可直接操作未加载线程，查询不为展示状态而启动推理；停止时先通知原生中断和暂停目标，再由共享进程管理器回收进程树。`request_user_input` 的问题和真实用户回答在聊天内往返；过期请求、错误参数及等待超时分别处理，超时不会伪造回答。失败时保留原输入供修改或重试，日志不记录目标正文、回答或凭据。
