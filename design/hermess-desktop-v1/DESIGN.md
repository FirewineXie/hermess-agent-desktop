# Hermess 桌面端交互设计稿

状态：设计方案，2026-10-26。这里的图片用于确定页面结构、视觉方向和交互，不代表截图中的示例数据、第三方连接或定时任务已经在产品中实现。

## 信息结构

左侧栏分为两个区域：

1. **全局入口**：新建会话、工作区、专家 · 技能 · 插件、定时任务、工具与能力。侧栏不设「更多功能」和「新建 Profile」按钮；暂不放「自动化」。
2. **已创建的专家（Profiles）**：专家以 Profile 为实体。侧栏同时列出已创建的 Profile 及其会话。点击名称或头像进入该 Profile 管理页；点击缩进的会话直接进入该会话的聊天页。浏览列表无需先切换全局 Profile。

顶部左侧展示「本地 / 远程」运行位置与连接状态；右侧依次为模型设置、GitHub、更新和系统设置。系统设置提供运行时与存储、关于；Agent 设置、人格与记忆、渠道和使用统计从所属 Profile 管理页进入。

**选中态规则**：打开全局页面时，只高亮对应全局入口；Profile 右侧可保留状态点，但不同时高亮 Profile 行。只有打开 Profile 管理页时，才高亮该 Profile 行。图片里与此规则不符的选中背景应按这条规则实现。

## 页面和交互

### 1. Profile 管理

![Profile 管理](screens/01-profile-management.png)

- 点击「大龙虾」进入其管理页；下方会话仍可直接打开聊天。
- 主区展示该 Profile 的技能、MCP、记忆和自身数据，分别有管理入口。
- Agent 设置、渠道和使用统计也从此页进入，并沿用该 Profile 作为操作上下文。
- 此页的数据与操作只属于当前 Profile；不把系统设置或其他 Profile 的配置混入。
- 「新建会话」从此处进入时，预选当前 Profile。

### 2. 新建会话

![新建会话](screens/02-new-chat.png)

- 页面核心是聊天输入框。左下角选择本次会话的 Profile；右下角选择模型并发送。
- 输入框下方选择工作区。发送第一条消息后创建会话，并归入所选 Profile。
- Profile 选择是**本次会话的上下文**，不是为了浏览其他 Profile 会话而切换一个全局状态。
- 模型名称、建议问题和头像是示例；实际选项来自产品数据。无模型可用时提供明确的配置入口。

### 3. 工作区

![工作区](screens/03-workspaces.png)

- 全局列表展示默认工作区与用户添加的本地目录，可添加、选择或移除目录。
- 从某工作区点击「新建会话」时，带入该目录，然后确定执行的 Profile。
- 已有会话继续使用自己的工作目录；变更默认选择不应悄悄修改已有会话。
- 图中的路径是示例，不能写成代码中的固定路径。

### 4. 专家 · 技能 · 插件

![能力目录](screens/04-capability-catalog.png)

- 「专家」分类展示预设专家；选用预设时，以其性格、技能和 MCP 配置创建独立 Profile。预设是专家的创建方案，创建后的专家就是 Profile，并出现在侧栏。不要把预设当成可安装到现有 Profile 的附属能力。
- 若需要空白 Profile，在专家分类提供「自定义专家」入口；侧栏不重复提供名称直建入口。
- 「技能 · 插件」「MCP」分类用于发现和配置能力；添加或连接时明确选择目标 Profile，弹窗展示实际权限与真实配置字段。
- 完成后，可回到目标 Profile 管理页查看已启用的能力。
- 图中的 GitHub、Notion 等目录项及授权文案仅是视觉示例。实现时使用实际支持的目录、元数据和连接流程，不硬编码示例权限或假装授权成功。

### 5. 定时任务

![定时任务](screens/05-scheduled-tasks.png)

- 全局列表聚合各 Profile 的任务；每行始终显示所属 Profile、下次运行时间和状态。
- 点击任务打开详情，显示计划、所属 Profile 和执行记录；新建任务时必须确定所属 Profile。
- 「立即运行」「编辑计划」只有在实际接口与权限支持时才可用。图中的任务、时间与状态均为示例。

## 实现边界

- 当前锁定 Gateway 支持一个进程服务多个 Profile，并支持请求携带 Profile。现有桌面聊天代码仍使用一个全局选中 Profile；要实现跨 Profile 直接打开和发送会话，需要给会话及其后续操作保留明确的 Profile 上下文。不要只做侧栏视觉分组。
- 连接状态点须有明确语义：Gateway 正在服务某 Profile、会话正在执行、渠道已连接是三种不同状态，不能共用一个含糊的「在线」。
- 这些图是设计目标。实现前按当前 `HermessAgentDesktop` 源码、契约和锁定运行时核对功能；缺失的接口、数据或状态要如实列出并实现或标明未完成。
- 视觉参考优先于历史页面布局；现有功能和数据隔离边界仍须保留。不要复制 `cankao/` 项目的代码或素材。
