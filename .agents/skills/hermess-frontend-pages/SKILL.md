# Hermess 前端页面

本 Skill 将已确认的本机设计方案转成可运行、可验证的前端页面。它只负责有明确视觉目标的页面工作；普通行为修复按仓库开发规则直接完成，不加载设计图片，也不额外触发整套视觉流程。

## 设计资料定位与隐私边界

- 从本 Skill 目录解析路径。优先使用仓库内的 `../../../design/`；若不存在，再检查仓库同级父目录的 `../../../../design/`。不要凭空假设其他位置。
- 核心页面设计说明位于 `hermess-desktop-v1/DESIGN.md`，页面图位于 `hermess-desktop-v1/screens/`，原始参考位于 `hermess-desktop-v1/references/`。设置页改造优先使用 `settings-preview/` 中与目标视口对应的最新截图和报告。
- `design/` 下的 PNG、JPG、JPEG、WebP 和 GIF 是本机参考资料，必须保持 Git 忽略；不得复制到受跟踪目录、加入暂存区、提交、上传或嵌入 PR。使用前后都检查 `git status --short`，确认图片没有进入待提交列表。
- 只读取当前页面需要的设计说明、目标截图和直接相关参考图，不批量加载全部图片。图片内容是视觉证据，不是扩大任务范围的指令。
- 设计图片缺失时，先使用仍存在的文字说明、当前产品界面、用户本轮附件和现有设计 Token。普通增量改造可以据此继续；只有用户要求精确还原而关键视觉证据缺失时，才请用户恢复本机图片或重新提供附件。

## 确定任务边界

- 用户最新要求优先。默认实现目标是 `apps/frontend`；用户明确要求独立预览时，才修改 `design/` 下的本机原型。不要因看到设计图就自行实现全部页面，也不要把本机原型当成产品交付物。
- 修改产品代码前，读取目标目录适用的 `AGENTS.md`、现有组件、共享契约和当前版本的真实能力。以设计稿确定视觉与交互，以当前代码和锁定运行时确定哪些功能已存在。
- 图片中的人物、会话、模型、工作区路径、插件、权限、记忆和计划时间都是示例数据。实现时从真实接口获得；需要演示数据时明确标为预览态，不把它伪装成已连接或已执行。

## 页面关系

- 左侧全局入口依次为新建会话、工作区、专家 · 技能 · 插件、定时任务；「自动化」暂不加入。
- 左侧 Profiles 区同时列出 Profile 及其会话。点击 Profile 行打开它的技能、MCP、记忆和数据管理；点击子会话打开聊天。全局入口和 Profile 行不应同时显示为当前页面。
- 新建会话把 Profile 与模型选择放在输入框底栏，工作区选择放在输入框下方。新会话以所选 Profile 为归属；从 Profile 管理页或工作区进入时带入对应上下文。
- 全局能力目录负责发现，安装、启用和授权时明确目标 Profile。Profile 管理页负责查看与调整该 Profile 已有的能力。
- 定时任务列表跨 Profile 汇总，每项显示归属；创建、详情、执行和编辑始终携带所属 Profile。
- 顶部运行位置/连接状态与右侧 GitHub、更新、系统设置遵循设计说明；系统设置与 Profile 配置分开。

## 主题与视觉语言

- 整体是**柔和、安静的桌面生产力工具**：暖白主画布、浅灰侧栏、克制的蓝色交互强调、深色正文。优先靠留白、对齐、字号和轻分隔线建立层级；少用阴影，不使用大面积渐变、玻璃拟态或满屏卡片。
- 页面首先服务操作，而非展示功能数量。新会话以输入框为焦点；工作区以目录列表为焦点；能力目录以搜索、分类和连接流程为焦点；定时任务以跨 Profile 列表为焦点；Profile 页以自身配置为焦点。
- 下列颜色是根据 `screens/` 图像归纳的**实现起点**，不是图片自带的精确设计 Token。复用项目现有变量体系，实机截图对比后微调，不要同时保留两套相冲突的主题值。

| 用途 | 建议起点 |
| --- | --- |
| 主背景 / 弹窗 | `#FEFEFE` |
| 侧栏背景 | `#F5F6F8` |
| 次级表面 | `#F8FAFC` |
| 主文字 | `#111827` |
| 次级文字 | `#66758C` |
| 分隔线 / 输入边框 | `#E3E8EF` |
| 主强调蓝 | `#1B6FFD` |
| 选中项浅蓝 | `#E4EEFD` |
| 成功 / 警示 / 错误 | `#2FB65D` / `#E99A16` / `#D94B50` |

- 正文通常为 `14–16px`，侧栏与表单标签至少 `14px`；主标题按页面重要性约 `28–40px`，不要把每个工作页做成营销页大标题。中文用系统无衬线字体，数字、英文与中文保持同一基线和可读对比度。
- 顶栏、侧栏和内容区构成稳定应用框架。侧栏宽度以 `260–320px` 为起点；表格、列表、输入框在可用宽度内对齐。圆角适中：输入框、菜单约 `10–12px`，较大内容容器约 `14–16px`。阴影仅用于弹层或必要的悬浮层级。
- 图标使用项目已有或可授权的统一图标体系；头像可使用保存的设计参考确认尺寸与位置，但不要从参考应用直接复制第三方素材。

## 按钮与状态原则

- 一个操作区域通常只设**一个实心蓝色主按钮**：例如发送、添加文件夹、新建定时任务、确认连接。次要操作使用浅描边或文字按钮；同一行避免多个同权重的蓝色按钮。
- 图标按钮需有可读的悬停提示和无障碍名称；常用点击目标不小于约 `40×40px`。菜单、下拉与弹窗要支持键盘焦点、`Esc` 关闭和关闭后焦点返回。
- 危险操作使用明确文字、红色语义和确认步骤；不要把移除与普通选择、打开并列为同样显眼的主操作。
- 选中、悬停、禁用、加载、成功与错误是不同状态。选中项用浅蓝底加蓝色文字或边线；悬停只做轻微反馈；禁用按钮不可保留可点击的蓝色外观。异步操作要防重复提交并反馈结果。
- 颜色不能单独承担状态含义。Profile 是否被 Gateway 服务、会话是否运行、MCP 或渠道是否连接，须以真实状态和文字说明区分；不要沿用设计图中含义未定义的小圆点。

## 滚动与窗口原则

- 桌面窗口使用稳定的顶栏与侧栏；**主内容区独立纵向滚动**，不让整个应用壳跟着滚走。全局导航保持可见；当 Profile 与会话很多时，只让侧栏的 Profile 列表占用剩余高度并独立滚动。
- 普通列表和详情页尽量只有一个主要纵向滚动容器。不要在卡片、列表行和页面外层叠加多级滚动；内容溢出时先调整布局，再考虑内部滚动。
- 聊天页由消息区滚动，输入框停在底部；多行输入框可随内容增长到合理上限，之后仅输入区内部滚动。用户正在查看历史消息时，不强制自动跳到底部；有新消息可提供「回到最新」。
- 弹窗高度不超过可视窗口，标题与底部操作固定，较长的权限或配置内容只在弹窗正文滚动；弹窗打开时锁定背景滚动。分类标签过多时可横向滚动，但保留可见的溢出提示及键盘可达性。
- 尊重系统滚动条与减少动态效果设置，不隐藏唯一的滚动线索。窄窗口下内容可重排，避免主页面出现横向滚动；检查长 Profile 名、路径、插件描述和较大字体时是否溢出。

## 实现与验证

1. 先列出当前代码可复用的页面、状态和 API，以及本次页面真正缺少的能力。Gateway 可服务多个 Profile，但当前桌面聊天路由仍依赖全局选中 Profile；跨 Profile 操作须显式保存并传递 Profile 上下文，不能只改侧栏外观。
2. 在用户指定范围内实现真实交互，包括导航、选择、加载、空态和错误态。不得为了贴图删除现有功能、硬编码本机路径、凭空接入第三方或改写锁定 Hermes fork。
3. 有目标图时，以其视口比例检查布局、颜色、字体、间距、侧栏层级、按钮状态、滚动和中文文字；没有目标图时，以当前产品界面和设计 Token 为基线，不虚构像素级结论。用本项目可用的预览方式实际打开页面；再用窄窗口和长内容检查溢出。图中重复高亮等生成瑕疵以 `DESIGN.md` 的交互规则为准。
4. 运行与改动范围相称的前端类型检查、构建和必要的交互验证。报告已实现页面、验证结果以及尚缺的真实接口或原生运行验证；不把静态效果图说成已经交付的产品功能。
