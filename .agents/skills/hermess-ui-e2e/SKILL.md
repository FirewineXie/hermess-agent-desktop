# Hermess 页面 E2E 测试

## 选择入口和工具

1. 从用户实际操作的入口开始，核对页面组件、预览路由和宿主能力。为每个场景写清初始状态、操作、可见反馈和业务结果，覆盖本次涉及的主路径和相关失败、取消或重试分支。
2. 验证 React 页面交互时，参考 [前端说明](../../../apps/frontend/README.md)，在仓库根目录运行 `pnpm --dir apps/frontend dev`，默认地址为 `http://127.0.0.1:1421`。端口被占用时先核对现有服务的项目和入口，或为本轮服务指定空闲端口。全局导航从 `/` 进入，专项场景在 `apps/frontend/*.html` 及 `apps/frontend/src/preview/` 中查找匹配的预览和模拟数据。根命令 `pnpm dev` 启动的是桌面项目的前端。
3. 优先用当前环境可用的浏览器自动化。需要用脚本驱动本机 Chromium 时，可复用 [仓库的 CDP 工具](../design-taste-frontend/scripts/lib/cdp.mjs)，它使用 Node.js 22+ 和已安装的 Chrome、Edge 或 Chromium。用 `Browser.launch()`、`newPage()` 和 `goto()` 打开隔离会话，用 `page.send()` 发送真实输入，用 `page.eval()` 查询界面，用 `page.screenshot()` 留证，在 `finally` 关闭浏览器。该工具会自动取消 JavaScript 原生确认框，验证确认分支时选用能显式处理弹框的工具。临时脚本和产物可放在 Git 忽略的 `.build/` 下。
4. 涉及 Tauri 原生窗口、系统对话框、快捷键或拖放时，按 [桌面开发说明](../../../apps/desktop/README.md) 使用对应环境和隔离测试数据。Windows 的 WebView2 和 macOS 的 WKWebView 分别验证。

## 验证页面交互

- 优先按角色、可访问名称、标签或现有 `data-testid` 定位。像用户一样点击、输入、滚动或按键，等待目标状态出现。用可见内容、焦点、按钮状态、列表结果或重新打开后的数据作为断言；保存与重试要验证操作结果。内存模拟中的重新打开只能验证本次会话内的保存。
- 根据本次变更补测相关状态。表单检查提交条件和错误反馈，弹窗检查取消及焦点归还，异步流程检查加载、失败和重试，窄窗口有影响时检查滚动与控件是否可达。通过有超时的状态等待同步测试，避免用固定延时猜测页面是否就绪。
## 验证业务逻辑和真实 Gateway

1. 用当前仓库已有的针对性测试检查业务规则，再用页面操作或真实接收方检查对应结果。根据功能覆盖有效与无效输入、状态转换及作用范围。写入后从独立查询或重新打开的页面回读，必要时检查磁盘或重启后状态。被拒绝的操作应断言错误与数据未被改动。涉及 Profile 时，用两个隔离 Profile 的同名数据检查操作只影响目标。
2. 页面功能经过 Gateway 时，运行 `pnpm verify:upstream` 核对 [锁定上游](../../../runtime/upstream.lock.json)，追踪 React、共享契约、Tauri、Rust 请求构造及锁定接收方。对照本次实际调用的路由或 RPC、参数、鉴权和 Profile 作用范围，选择并核对已有验证脚本的输入与断言，再向真实锁定 Gateway 发送生产形态的请求。断言实际接受或拒绝、返回值及数据副作用。
3. 使用本轮启动的本地 Gateway、临时数据目录、合成 Profile 和测试凭据。需要模型回包时可使用本地合成模型，Gateway 本身仍运行锁定的真实实现。环境可用时，从桌面 UI 触发请求并验证回读结果。分别执行浏览器预览和直接 Gateway 请求时，按各自验证范围记录；桌面整链路未实跑就标为未验证。

## 记录结果

- 按场景报告通过、失败或未验证，注明平台、入口、工具和用例。区分页面模拟、业务逻辑测试、真实 Gateway 请求及原生 UI 到 Gateway 的整链路。
- 失败时记录入口、测试数据、复现步骤、预期与实际结果，以及相关控制台异常、Gateway 日志或截图。避免记录凭据和用户数据，只关闭本轮启动的进程。需要纳入仓库的前端回归用例放在 `apps/frontend/tests/`，数据由用例构造。

## 示例

打开 `/journey-preview.html`，点击 `hermess-desktop-guide` 学习记录。断言详情打开、焦点在编辑框且保存按钮禁用。输入新内容，保存后重新打开核对，再按 `Esc` 确认详情关闭且焦点回到记录入口。

真实 Gateway 用例在两个隔离 Profile 中准备同名且具有学习记录的测试 Skill。用生产形态的图谱和节点请求验证读取、修改、回读及归档，确认目标 Profile 的落盘内容和列表结果。验证无权读取和更新不存在的节点会被拒绝，同时核对另一个 Profile 的同名记录仍可读取且内容正确。
