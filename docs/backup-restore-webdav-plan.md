# 备份、还原、定时备份与 WebDAV 方案

状态：方案，尚未实现或验收。日期：2026-10-29。目标版本待排期；本文不表示 v0.1.8 已包含这些能力。

## 目标与边界

为 Hermess Agent Desktop 提供同一种可恢复的备份格式，支持手动备份、定时备份、本地还原和 WebDAV 上传、下载还原。备份与还原只处理本产品的数据，不接管用户另行安装的 Hermes。Windows 和 macOS 共享归档格式、清单、校验、调度状态及还原规则；系统任务、凭据安全存储、路径和权限由平台适配层实现。

第一版每次生成**一份独立的轻量配置备份**，不依赖上一次备份；手动、定时和 WebDAV 使用同一种归档。“完整”只指本方案选定的五类内容：配置、凭据、Profile 定义、Agent 定时任务定义、渠道配置与认证。它不代表整个 `hermes-home` 的数据备份。还原只替换这些被选中的配置项，保留聊天等未备份数据。

不把聊天记录、执行历史、记忆内容、附件、Skill/插件代码与数据、用户另选的工作区文件夹、系统现有 Hermes 安装、应用二进制和运行时资源纳入归档。外部记忆提供方的数据也不备份。界面须称为“配置备份”，并列出未覆盖项目，不能显示“所有数据已备份”。系统应用配置、WebView `localStorage`、浏览器登录状态和本机工具安装也不随归档迁移。

## 当前实现依据

- 桌面端把所选存储位置下的 `HermessAgentDesktop/hermes-home` 作为自有 Gateway 的 `HERMES_HOME`，在 `HermessAgentDesktop/control` 持有存储锁；所选位置另记在系统应用配置目录的 `storage-location.json`。见 `apps/desktop/src-tauri/src/runtime/mod.rs` 与 `runtime/location.rs`。
- 关闭窗口会隐藏到托盘；托盘「退出」会停止产品进程并退出后台。应用内计时器不能保证完全退出后的备份。见 `apps/desktop/src-tauri/src/tray.rs`。
- 当前 Hermes 锁文件为官方 `v0.22.5` 基线上的 fork 提交 `882037eb8745b505db438217513c4c94f95c93c1`。锁定源码的 `hermes backup` 是整 Home 备份，超出本方案范围；桌面端没有产品级配置备份入口。见 `runtime/upstream.lock.json`、`upstream/hermes-agent/hermes_cli/backup.py`。
- 不能把 `hermes backup` 或 `hermes import --force` 直接接到桌面按钮：前者会收集会话等大量数据及部分产品外数据；后者按归档成员写入，还可能恢复用户主目录中的外部记忆数据、创建 Profile CLI 别名及尝试启动服务。桌面端应基于白名单独立实现选择性备份与还原，默认不修改 fork。
- Hermes 的 Profile 定时任务属于 Agent/Gateway 功能，不适合作为产品数据备份的唯一调度器：待备份的 Gateway 停止或应用完全退出时，它也不能保证执行。产品备份计划由桌面宿主与系统调度适配层管理。

上述是当前源码核对，不是备份功能的运行验证。开发时须重新核对锁文件及上游行为。

## 归档内容和格式

归档只按白名单读取默认 Profile 的 `hermes-home/` 与命名 Profile 的 `hermes-home/profiles/<名称>/`。下表是当前锁定代码可以确认的路径与目标内容；实际开发须逐项核对读写方，不把整个 Profile 目录打包。

| 类别 | 备份内容 | 路径与边界 |
| --- | --- | --- |
| 配置 | 模型、提供商、Agent 行为、MCP、渠道和工具开关等设置 | 每个 Profile 的 `config.yaml`；配置文件整体保存，恢复前检查版本与外部路径 |
| 凭据 | 模型密钥、OAuth 授权、MCP 令牌及 Hermes 凭据保险箱 | 每个 Profile 的 `.env`、`auth.json`、`vault.key`、`vault.json.enc`、`mcp-tokens/` 等经读写方核实的凭据文件；不按“凭据目录”名称盲目递归 |
| Profile | Profile 名称、说明、角色设定及创建时的重要标记 | 命名目录的存在性、`profile.yaml`、`SOUL.md`、`.no-bundled-skills` 与该 Profile 上述配置/凭据；默认 Profile 按根目录处理。`SOUL.md` 属角色设定，`MEMORY.md`、`USER.md` 等内容文件不在范围内 |
| Agent 定时任务 | 各 Profile 的任务定义、启停状态、表达式、执行内容与投递配置 | 各 Profile 的 `cron/jobs.json`；不备份 `cron/executions.db` 及执行日志。备份功能自身的系统计划和 WebDAV 凭据不随归档迁移 |
| 渠道 | 渠道启用与连接配置、必要的配对及认证状态 | `config.yaml` 中的渠道配置、`.env` 中的令牌，及经核实的 `pairing/`、`platforms/pairing/`、渠道认证文件；聊天消息、群成员缓存和连接临时状态不包含 |

渠道或凭据可能与消息记录共存在同一数据库或目录。实现时必须逐一核对；能安全提取认证和配置的才纳入。若无法在不带出聊天数据的前提下提取，就排除该项，并在备份详情明确提示“此渠道还原后需重新授权”，不能悄悄打包整个数据库。

`cron/jobs.json` 中可包含任务文本、内联脚本和 Skill 名称，但任务引用的工作区文件、外部脚本路径或未备份的 Skill/插件实体不随归档迁移。还原后核对依赖与目标路径；无法运行的任务应暂停并给出明确原因，不让它在下一次调度时静默失败。

明确排除：`state.db`、`response_store.db`、`cron/executions.db` 等会话和执行历史数据库；`sessions/`、`memories/`、`MEMORY.md`、`USER.md`、个人文件、Skill/插件代码及数据、附件和媒体、浏览器 Profile/Cookie、安装目录中的客户端与运行时、下载工具及依赖、可重建缓存、日志、PID、锁、Gateway 临时状态、既有备份。产品根的 `model-candidates.json` 是可重新建立的本机候选表，不在本方案范围。不能因为整个 `config.yaml` 中存在“记忆设置”，就把记忆内容也视为已备份。

每份归档都能独立还原：例如周一、周二各完成一次，删除周一归档不影响周二还原。首版不做增量或跨归档去重；由于只收集配置类小文件，预计归档明显小于整 Home 备份，但具体大小必须以真实数据统计，不能预设固定体积。设置页展示实际大小；空间不足时停止新备份且保留已有有效归档。

统一归档格式建议为一个带版本头的加密文件，内部包含 `manifest.json` 与数据文件。清单记录格式版本、创建时间、产品版本、锁定 fork SHA、源操作系统、Profile 名称、备份范围和排除项、每个已备份文件的相对路径/大小/SHA-256，以及白名单中经确认在源端不存在的可选文件；“未包含”和“源端不存在”不能混为一谈。归档只使用相对路径；读取时拒绝绝对路径、`..`、符号链接或 Windows 重解析点越界、重复路径、大小异常和解压炸弹。完整性校验同时覆盖清单与文件，不能仅凭 ZIP 可打开或 WebDAV 返回成功认定可还原。

归档含模型密钥、渠道令牌等敏感数据。**本地与 WebDAV 使用相同的加密归档**，数据在离开本机前完成加密；界面不显示密钥原文。可采用经过审查的带认证加密格式与随机数据密钥，清单中只暴露识别归档必需的最少元数据。具体加密库与文件格式在实现阶段选定并固定版本，补充跨版本解密测试，不能自行拼接未审查的密码学算法。

定时任务需要无人值守使用数据密钥：日常解锁材料放在 Windows 用户凭据保护设施或 macOS Keychain；另提供用户自行保存的跨机器恢复密钥，并要求在启用定时或 WebDAV 前完成一次恢复密钥校验。系统凭据设施不可用、账户未解锁或用户丢失恢复密钥时，明确报错，不降级保存明文。WebDAV 登录凭据单独保管，不进入备份归档；换机器后重新配置。

## 备份事务

1. 取得本产品存储归属及备份互斥权，确认目标路径不在任何待备份目录内、空间足够，创建不可被列表识别为有效备份的临时文件。
2. 检查活动 Agent、审批、渠道和定时任务。手动备份展示等待状态；自动备份在繁忙时顺延并重试，不强杀任务。空闲后暂停新的 Gateway 操作，停止自有 Gateway 与相关写入进程，确认退出。若停止失败，本次不生成“成功”归档。
3. 在写入静止期间只复制白名单文件和 Profile 名录到受控临时目录，逐项记录存在/缺失、大小与校验值；若任务开始前 Gateway 正在运行，随后恢复该自有 Gateway；若由完全退出后的系统调度启动，则不额外启动 Gateway。压缩、加密、校验和 WebDAV 上传从临时副本继续。
4. 验证归档格式、文件清单、配置可解析性与校验值后，才把临时文件原子发布为本地正式备份，并记录备份 ID。必需配置文件读取失败则整个备份失败；可选认证项因范围边界被排除时以明确的“需重新授权”提示随归档保存，不能把归档标成无遗漏。
5. 本地备份成功与远端上传成功分别记状态。仅在新备份完成且可验证后执行保留策略；不得因一次失败删掉最后一份有效备份。

备份位置应在 `HermessAgentDesktop/backups` 或用户选定的产品外部目录，不能放进待备份的 Profile 配置目录，也不能让白名单扫描进入 `backups`。若目标在网络盘或不同卷，先在本地受控目录完成归档，再复制并校验目标；跨卷复制不能宣称原子发布。

## 定时执行

设置项：启用状态、每天/每周、当地时间、保留份数、WebDAV 是否同步、网络失败重试策略。建议初始值为每天 03:00、本地保留 7 份、远端保留 30 份；这些仅为待确认的产品默认值。页面显示下次计划、上次本地成功、上次远端成功、正在执行的阶段、最近错误和手动“立即备份”。计划按本机时区计算；时区变化、夏令时和休眠恢复后，以计划执行 ID 去重，每个周期最多补做一次。

应用在托盘运行时由宿主调度；应用完全退出时由 Windows 任务计划程序或 macOS LaunchAgent 启动无窗口的一次性产品备份任务。启用、修改和关闭计划时同步创建、更新或移除**本产品创建的**系统任务；应用更新后检查任务指向的可执行文件是否仍有效，失败时提示修复。系统任务不启动另一个可见窗口，也不使用用户现有 Hermes 的 CLI 服务。

运行中的桌面实例持有产品存储锁，因此系统任务不能绕过锁直接复制数据。系统触发时：若桌面实例存在，通过经本机身份校验的产品 IPC 请求其执行；若实例不存在，一次性任务自行取得存储锁并执行备份，完成后释放资源退出。两条路径共用同一个备份状态机和备份 ID。若无法完成安全的 IPC 握手，则本次顺延，绝不能强行打开同一数据根。桌面实例启动的辅助进程由现有进程管理器登记；系统启动的一次性任务在自身进程内初始化相同的进程管理与子进程树清理规则。Windows 后台执行不闪现控制台，macOS 验证 LaunchAgent 的登录会话和 Keychain 可访问性。

错过计划时在下次唤醒或启动后补做一次；网络断开只影响远端队列，不重复生成同一份本地归档。重试采用有上限的退避，认证失败和恢复密钥不可用需等待用户处理。一次任务始终以开始、关键状态变化、完成或失败日志闭环，日志包含操作 ID、阶段、错误类别、耗时和字节数，不含 URL 凭据、密钥、文件正文或令牌。

## WebDAV 传输

页面提供 HTTPS 地址、用户名、应用密码、远端专用目录、「测试连接」、上传与下载状态及远端备份列表。宿主统一执行请求；前端只拿脱敏状态。禁止 URL 用户信息、明文 HTTP、跨站认证重定向和自动信任无效证书。服务器地址与路径分别规范化，所有写入与删除都约束在用户选定的产品专用目录内。

连接测试实际验证目标目录的 `PROPFIND`、`MKCOL`、`PUT`、`GET`、`MOVE` 与按保留策略需要的 `DELETE`，不能只根据登录成功判断可用。WebDAV 方法及状态语义以 [RFC 4918](https://www.rfc-editor.org/rfc/rfc4918.html) 为准；实现须处理 `207 Multi-Status` 的逐项结果。首版若服务器不能安全地把临时上传发布为正式文件，应明确报“不支持此服务器的可靠备份”，不默默降级为可能被误列为可恢复的半成品。

上传顺序：本地归档校验通过 → 以备份 ID 上传远端临时名 → 核对远端长度并通过 `GET` 流式回读计算摘要 → `MOVE` 到唯一正式名且禁止覆盖 → 再次确认正式对象存在 → 标记远端成功。只在远端完整校验成功后进入可还原列表。网络中断、超时或空间不足时保留本地归档与待上传队列；重试使用同一备份 ID，检查既有临时/正式对象，避免重复备份。远端清理仅识别本产品清单和命名空间，不遍历删除用户其他文件。

从 WebDAV 还原：先下载到本地受控临时目录，完成归档认证、解密、文件校验、格式与空间预检，再进入本地还原事务。下载未完成或校验失败不能触碰当前数据。远端列表不可用时，本地备份仍可独立还原。

## 还原事务

还原界面在执行前展示备份时间、来源产品与 fork 版本、Profile、包含/排除范围、将被替换的配置项，以及未备份的聊天、记忆、附件与需重新授权的渠道。跨版本先执行配置兼容性检查；未知格式拒绝覆盖。跨机器恢复时沿用目标机器当前存储位置，不导入源机器的 `storage-location.json`、备份系统任务定义、设备偏好或 WebDAV 凭据。配置内指向旧机器工作区或程序的绝对路径可能无效，恢复后提示重新选择；引用缺失外部脚本、Skill 或插件的定时任务暂停并提示修复。

执行时阻止新操作，正常停止本产品 Gateway 及会写入目标配置的自有进程；待源归档在同卷临时目录完成解密和校验后，对白名单中的配置、凭据、Profile 元数据、任务定义与渠道认证文件逐项保存旧版本并发布新版本。备份中没有的现有 Profile 默认保留；同名 Profile 只替换本方案范围内的文件，不删除其会话、记忆或附件。归档内明确标记为“源端不存在”的范围内文件按规则移除，避免旧凭据或旧任务继续生效；范围外的文件一律保持。新增 Profile 的目录由本产品创建，不复制整目录。任一文件切换或 Gateway 启动、配置读取失败时，按事务日志撤销全部已改文件、移除本次新建的空 Profile 目录，再重新启动旧数据。两次启动结果均要记录；成功后保留配置回退副本到用户确认或预设期限。Windows 要处理残留文件句柄和目录改名失败；macOS 要处理权限及 Keychain 凭据不随归档迁移。

还原期间不修改用户独立 Hermes 的默认 Home，不执行上游 `hermes import --force`，也不运行会创建全局 CLI 别名或服务的安装动作。归档里的旧 PID、锁及 Gateway 状态永不恢复；重新启动时由客户端生成新的进程和会话身份。

## 页面与接口落点

- 在「设置 → 运行时与存储」增加「数据备份」区域：立即备份、计划、WebDAV 配置、本地/远端备份清单、下载、还原及结果。运行状态与错误应在离开页面后仍由宿主保留，重新进入可查询。
- 在 `packages/contracts` 增加备份计划、备份清单、任务状态和操作命令的类型；前端不接触原生文件系统、WebDAV 密码明文回读或加密密钥。
- 在桌面 Rust 宿主增加独立 `backup` 模块，统一持有调度状态和备份互斥；`runtime` 提供受控的暂停、停止和重启入口，`process_manager` 管理新增进程。平台适配层分别负责 Windows 任务计划程序/凭据设施和 macOS LaunchAgent/Keychain。
- 计划配置与任务状态存于本产品系统配置或数据目录；敏感材料放系统安全存储。归档、临时文件、队列与回退副本各有明确位置和清理规则，不能被备份递归包含。

## 实施顺序与验收

| 阶段 | 交付 | 必须验证 |
| --- | --- | --- |
| 1. 本地手动备份/还原 | 白名单配置归档、加密、清单校验、选择性替换与回退 | 多 Profile 的配置/凭据/任务/渠道；聊天与记忆保持原样；活动任务顺延；坏归档拒绝；启动失败回退；产品外 Hermes 不受影响 |
| 2. 定时备份 | 宿主调度、Windows/macOS 系统任务、补做、去重、保留策略 | 托盘、完全退出、重启、休眠、跨时区、任务繁忙、计划关闭、安装包升级后任务修复 |
| 3. WebDAV | 凭据安全存储、连接测试、加密上传队列、远端校验与下载还原 | 主流兼容服务的正常流程、认证失败、断网、限额、上传中断、同 ID 重试、远端损坏、删除范围、跨机器恢复密钥 |

每阶段按改动范围执行仓库真实存在的类型检查、构建、架构/契约检查、Rust 格式与测试，并在 Windows、macOS 分别做原生窗口和安装包验证。CI 构建、脚本冒烟与原生实机结果分别记录；未完成阶段保持“方案/开发中”，不标为已交付。开发完成后按仓库规则更新 `ROADMAP.md`，经版本分支和 PR 合入，默认不修改 Hermes fork。
