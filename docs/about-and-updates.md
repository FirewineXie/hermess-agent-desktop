# 关于页面与软件更新

## 已实现的范围

侧栏「关于」页包含致谢与许可、开发者工具授权、联系与反馈、软件更新四个 Tab。桌面程序通过宿主接口返回编译时产品版本、固定上游 tag 和 SHA，以及随程序内嵌的产品与上游许可证全文。浏览器预览只返回明确的模拟信息。

软件更新页将渠道偏好保存在当前桌面 WebView 的 `localStorage` 中。未设置时，RC 构建默认 RC 渠道，正式构建默认正式版渠道。页面没有可信发行源时显示不可检查，按钮禁用，不报告“已是最新”。私有仓库地址只用于识别项目，不是可公开访问的反馈入口或更新源。联系方式、逐项第三方声明、在线检查和安装恢复仍待交付。

## 版本和渠道规则

应用内候选选择只接受 `MAJOR.MINOR.PATCH` 与 `MAJOR.MINOR.PATCH-rc.N`，允许版本前带 `v`。版本三段及 RC 序号按整数比较；同一基础版本下正式版高于所有 RC。正式版渠道只选更高的正式版；RC 渠道可选更高的 RC 或正式版。每个候选还必须由可信发行清单标记为可升级，且其版本字符串与渠道一致。切换渠道不触发降级。

例如 `0.5.0-rc.1 < 0.5.0-rc.2 < 0.5.0 < 0.6.0-rc.1`。当前为 `0.6.0-rc.1` 时切到正式版渠道，如果清单最新正式版仍为 `0.5.x`，结果是等待新正式版，不是回退。规则实现于 `apps/frontend/src/features/about/updateRules.ts`，回归用例由 `pnpm test:update-rules` 执行。

## 接入真实更新所需的发行数据

发行源与对外联系方式确定后，先提供经验证的发行清单，再开放检查按钮。清单至少记录：完整版本和渠道、发行 ID、可升级标记、配套 Hermes SHA、适配和资源标识、平台/架构/安装形式、升级兼容边、发行说明、安装包 URL/字节数/摘要/签名。客户端读取后须校验来源和内容，再按上述规则选择候选；版本更高不等于一定能从当前发行组合安全升级。

当前 tag 工作流支持 RC 与正式版 Release，尚未产出供客户端信任的更新清单。接入前还需明确密钥与签名校验、公开发行源、不可变产物策略及撤回方式。在线检查应在 Hermes 后端未启动时也可使用。安装事务按 `桌面端迭代方案.md` 第 9 节执行，并分别验收 Windows NSIS、macOS 应用、Linux AppImage 与 deb 的更新路径。任何平台未完成安装与失败恢复验收前，界面不开放该平台的一键安装。
