# 关于页面与软件更新

## 已实现的范围

侧栏「关于」页包含致谢与许可、开发者工具授权、联系与反馈、软件更新四个 Tab。桌面程序通过宿主接口返回编译时产品版本、固定上游 tag 和 SHA，以及随程序内嵌的产品与上游许可证全文。产品原创代码采用 PolyForm Strict 1.0.0，允许非商业使用；修改、制作衍生作品、分发或商业使用均须事先取得 Firewine 的书面授权。上游和其他第三方材料仍适用各自许可证。浏览器预览只返回明确的模拟信息。

软件更新页将渠道偏好保存在当前桌面 WebView 的 `localStorage` 中。未设置时，RC 构建默认 RC 渠道，正式构建默认正式版渠道。点击「检查更新」后，桌面端匿名读取本项目公开的 GitHub Releases；只对 Windows x64、macOS arm64/x64 提供匹配的安装包。此实现不在客户端内置访问凭据。联系方式与逐项第三方声明仍待交付。

发现较新版本后，用户可将安装包下载到系统下载目录。桌面端下载前重新读取对应 Release 和附件，要求文件名匹配当前平台、体积符合限制且 GitHub API 提供 SHA-256 摘要；下载完成后校验字节数和摘要。同名文件只有摘要相同时才复用。当前不自动安装或恢复，也未验收原生窗口中的完整下载路径。

## 版本和渠道规则

应用内候选选择只接受 `MAJOR.MINOR.PATCH` 与 `MAJOR.MINOR.PATCH-rc.N`，允许版本前带 `v`。版本三段及 RC 序号按整数比较；同一基础版本下正式版高于所有 RC。正式版渠道只选更高的正式版；RC 渠道可选更高的 RC 或正式版。每个候选还必须是非草稿、预发布标记与版本渠道一致，且有当前平台的安装包及 GitHub API 摘要。切换渠道不触发降级。

例如 `0.5.0-rc.1 < 0.5.0-rc.2 < 0.5.0 < 0.6.0-rc.1`。当前为 `0.6.0-rc.1` 时切到正式版渠道，如果清单最新正式版仍为 `0.5.x`，结果是等待新正式版，不是回退。规则实现于 `apps/frontend/src/features/about/updateRules.ts`，回归用例由 `pnpm test:update-rules` 执行。

## 后续安全升级所需的发行数据

当前检查与下载依赖 GitHub API 的 Release 元数据及附件摘要，仍没有独立签名的发行清单。真正的一键安装前，清单至少应记录：完整版本和渠道、发行 ID、可升级标记、配套 Hermes SHA、适配和资源标识、平台/架构/安装形式、升级兼容边、发行说明、安装包 URL/字节数/摘要/签名。客户端读取后须校验来源和内容，再按上述规则选择候选；版本更高不等于一定能从当前发行组合安全升级。

当前 tag 工作流支持 RC 与正式版 Release，尚未产出供客户端信任的签名更新清单。一键安装前还需明确密钥与签名校验、不可变产物策略及撤回方式。在线检查不依赖 Hermes 后端。安装事务及失败恢复须分别验收 Windows NSIS 与 macOS 应用的更新路径；Linux 暂不接入。任何平台未完成安装与失败恢复验收前，界面不开放该平台的一键安装。
