# v0.1.8 委派路由、提供商同步与桌面能力

状态：代码实现与本地检查完成，原生窗口及真实服务验收范围见下文。实现日期：2026-10-29。

本批在 `feature/v0.1.8` 按当前客户端结构实现 M05、M07、A02；没有合入旧 settings 分支，不读取旧设备偏好键、不增加兼容路由或双写，不修改锁定 Hermes fork。

## 提供商同步 M07

入口：设置 → 模型 → 提供商，自定义提供商卡片中的“同步到其他 Profile”。内置提供商与直接来自主模型配置的 `direct-config` 条目不提供此操作。

1. 选择其他 Profile，点击“检查目标”。来源和目标均须由当前产品自有 Gateway 服务。
2. 目标存在相同 ID、名称或规范化地址的提供商时禁止同步。没有覆盖、替换或删除重建操作。
3. 宿主生成来源公开配置、目标目录、目标模型列表、目标主模型和 Gateway 纪元的摘要；执行前重新读取，变化时拒绝旧预览。
4. 执行使用新的提供商 ID，避免上游 upsert 选择已有记录。多目标分别执行、分别报告结果，不保证跨 Profile 原子事务。
5. 复制名称、地址、默认模型 ID、API 模式、上下文长度、发现开关、客户端模型目录，以及运行时支持的模型别名规范名称和推理强度元数据。
6. 不复制 API Key、OAuth 身份或自定义秘密请求头。目标需要单独配置认证；不改写目标主模型、回退链、辅助模型、MoA 或委派配置。
7. 创建后核对公开字段、凭据状态、别名元数据、客户端模型列表及目标主模型。后续步骤失败显示“已创建但未完整核实”，保留新 ID，不自动重复创建或删除。

当前上游没有条件创建接口；客户端在预览和执行前检查冲突，独立新 ID 保证不选择既有提供商。外部客户端在最后一次检查之后并发新建同名供应商时，可能出现同名条目，不能把这一检查描述成服务端原子唯一性保证。

## 委派路由 M05

入口：设置 → 模型 → 委派路由。每次读写均显式携带 Profile，并使用锁定运行时的以下正式接口：

- `GET /api/delegation/routing`
- `PUT /api/delegation/backends/model_map`
- `PUT /api/delegation/backends/profile_routes`
- `PUT /api/delegation/backend`

支持默认策略、模型路由、Profile 路由，运行时未注册或不可用的策略不可选择；已有无效策略保留可见并显示阻塞原因。编辑不会立即写入。存在草稿时须先保存或重新读取，才能切换策略。

模型路由包含名称、任务描述、提供商或 HTTP(S) 地址、模型、API 模式、推理强度、请求速度、有序回退链、JSON 请求覆盖及默认路由。提供商和模型候选复用当前 Profile 的目录，也允许填写明确的自定义值。Profile 路由只能选择运行时返回的真实 Profile。

密钥操作明确分为保留、替换、清除。宿主只向前端返回是否已配置；保留和改名时由宿主将运行时的遮盖标记与原路由名交回专用接口，不读取明文密钥给前端。请求覆盖必须是有效 JSON 对象，最大 16 KiB。

保存先校验，再保存当前策略的配置，最后启用策略并重新读取。默认策略中的普通 `delegation.*` 字段使用既有 Schema 保存接口。接口不提供跨字段、路由配置和活动策略的单一事务，失败可能已经保存部分配置；页面要求重新读取核对，不自动重试。保存成功需要回读内容和凭据状态一致。

Agent 通用 Schema 表单不再重复编辑 `delegation.*`；完整 YAML 仍可编辑完整配置，专用页不维护独立配置副本。

## 桌面能力 A02

入口：设置 → 桌面 → 设备偏好 / 快捷输入。宿主在产品应用配置目录保存 `desktop-preferences.json`，不写入 Profile，不使用 localStorage 或历史偏好键。启动读取错误会显示错误并使用默认偏好，不阻止整个客户端启动。

设备偏好：

- 运行时保持唤醒：Windows 使用 Power Request，macOS 使用 IOKit 电源断言。只在本产品持有的后端进程仍运行时申请，检测间隔为 2 秒；关闭开关或托盘退出立即释放。不会阻止用户主动休眠。
- F12：Windows WebView2 使用宿主开关；macOS 显示不可用。删除原来的隐藏 `debug` 按键解锁、运行时页 F12 开关及旧原生命令。运行时页保留独立的日志诊断显示，不承担 F12 配置。

快捷输入：

- 默认快捷键 `CommandOrControl+Shift+Space`，默认关闭。必须包含修饰键；Windows 使用 Ctrl，macOS 使用 Command。
- 注册新快捷键失败时保留原设置；持久化失败时撤销新注册。快捷键只注册在当前 Tauri 进程，不启动辅助进程。
- 呼出独立窗口，显示 Profile 和会话。目标变化后须刷新确认；主窗口有草稿、附件、运行中任务或导航操作时禁止发送，不隐式排队。
- 使用请求 ID、宿主一次性领取和主窗口目标复核防止重复提交。消息进入现有聊天控制器，与普通聊天使用同一发送路径。
- 成功确认后隐藏并清空草稿；失败保留文字和错误。35 秒未确认会提示检查主窗口，保持等待且不自动重发，避免网络不确定时重复发送。主窗口或 WebView 异常退出后的待决请求不做自动恢复。
- Esc、失焦和关闭按钮隐藏窗口并保留草稿。托盘退出注销快捷键、释放电源断言并销毁输入窗，然后继续共享进程管理器的退出顺序。
- Windows 和 macOS 共用界面、契约及发送逻辑；系统唤醒、快捷键和窗口焦点由各自宿主实现。快捷输入窗仅开放必要的事件监听与隐藏窗口权限。

## 复核修复（2026-10-29）

- 快捷输入在调用 IPC 前生成并登记请求 ID；原生结果监听就绪后才允许发送，结果早于提交返回也能正确结算。宿主保留最近 128 个请求 ID，拒绝重复投递。新增即时回包、重复提交和已完成请求重放测试。
- 设备状态轮询不能回写保存前的旧值，也不覆盖正在编辑的快捷键。电源错误独立维护，避免隐藏快捷键注册错误；主线程的热键处理和状态读取在设置锁占用时不等待，防止与快捷键注册的主线程调度形成互锁。
- 委派回读只清理路由层的客户端字段，完整保留请求覆盖参数中的 null、空数组、空对象以及同名 JSON 字段进行比较，避免错误报告“已核实”。
- 供应商同步核对运行时返回的模型集合，凭据状态缺失时不报告核实成功。共享模型目录写入使用同目录临时文件、同步及重命名；Windows 目标文件被占用导致替换失败时，旧文件保持完整且临时文件被清理。
- 本地独立开发版已实际启动，窗口标题为“Hermess v0.1.8 本地调试”，通过开发标识与已安装版的单实例锁和设备偏好隔离；使用既有产品开发数据目录，后台记录 backend_ready。临时 Tauri 配置和启动日志仅位于已忽略的 .build。原生自动化无法完整读取窗口内容，因此此项仅记录启动与后台就绪，不升级为完整功能实机验收。
