# 桌面斜杠命令接入与禁用方案（待审核）

状态：第一批已实现，第二批 `/save` 已接入；Windows 本地检查与隔离 Gateway 验证通过，双平台原生窗口待验收。核对日期：2026-10-30。适用范围：Hermess Agent Desktop 当前开发分支与 `runtime/upstream.lock.json` 锁定的 Hermes fork；不定义 Hermes CLI 或消息平台的命令政策。

## 1. 目标与审核结论

桌面输入框只应提供能在当前产品内完成、能显示结果并能正确处理失败的命令。命令目录可用于发现名称和说明，但不能作为执行权限或桌面适配完成的证明。

本方案把命令分为四种决定：

| 决定 | 含义 |
| --- | --- |
| 接入现有桌面能力 | 复用当前页面、聊天操作或宿主能力；只有语义一致时才保留同名 `/命令`。 |
| 新增桌面功能 | 有产品价值，但需先定义状态、数据所有权、失败与恢复，再实现对应功能。完成前禁用同名命令。 |
| 暂不接入 | 当前缺少完整的产品入口或明确需求；不展示为可执行，后续可单独立项。 |
| 禁止桌面执行 | 终端专属、宿主边界不符或会造成错误语义；桌面候选不显示为可用，直接输入也拒绝。此决定不影响 Hermes CLI。 |

**建议第一批只做命令目录与执行边界的统一，以及现有桌面能力的映射。** 新增功能分别实施和验收，不因为本方案获批就宣称它们可用。

## 2. 当前代码事实与边界

1. `apps/frontend/src/features/chat/useChatController.ts` 直接处理 `/new`、`/sessions`、`/model`。其他斜杠命令先查目录和 `commandSupported`，随后通过 `chat.executeCommand` 进入 Rust 的 `execute_composer_command`，转发锁定 Gateway 的 `slash.exec`。`send` 返回值仍需由客户端以自己的输入 ID 提交，不得在 Gateway 侧重复提交。
2. `apps/frontend/src/features/chat/model.ts` 的 `DESKTOP_GATEWAY_COMMANDS` 是前端静态允许集合；插件命令和 Skill 另有动态分支。它与 Gateway 命令目录的 `desktop` 标记并非同一份策略。当前 Rust 入口只检查会话 ID、斜杠前缀和长度，尚未在宿主侧限制命令名与子命令。
3. 锁定 fork 的 `hermes_cli/commands.py` 声明命令目录、`cli_only`、`desktop` 与部分 `desktop_subcommands`；`gateway/session_commands.py` 再按具体命令与参数给出 `read`、`control` 或 `refused`。例如 `/skills` 只允许桌面使用待审批事项的部分子命令；`/cron` 的读取与写入在本地会话上有不同边界。目录可列出而执行仍可能被拒绝。
4. 当前锁定信息是 Hermes fork 提交 `882037eb8745b505db438217513c4c94f95c93c1`、官方基线 tag `v0.22.5`。本方案不修改该 fork；实施前仍须重新核对锁文件和实际检出。
5. 产品已有会话列表、会话恢复、当前会话停止、模型设置、工具与扩展、定时任务等入口。下文标为“映射”的命令仍须逐项比对 CLI 原语义；页面存在本身不等于命令的所有子功能可用。

核对入口：`apps/frontend/src/features/chat/model.ts`、`apps/frontend/src/features/chat/useChatController.ts`、`apps/desktop/src-tauri/src/runtime/chat.rs`、`upstream/hermes-agent/hermes_cli/commands.py`、`upstream/hermes-agent/gateway/session_commands.py`、`upstream/hermes-agent/gateway/session_discovery.py`。

## 3. 尚未接入的 51 个命令：逐项决定

“第一批”指策略与现有能力映射；“后续”指独立功能任务。对没有证明 Gateway 可接受的操作，不通过 `slash.exec` 猜测性透传。

### 3.1 会话历史与文件检查点（8 个）

| 命令 | 决定 | 桌面行为或禁用理由 |
| --- | --- | --- |
| `/history` | 第一批接入 | 打开当前 Profile 的会话历史；若用户要查看当前会话全部消息，滚动到该会话记录。不要复刻 CLI 的终端输出。 |
| `/save` | 第二批已接入，原生待验收 | 导出当前会话，支持 json/md/html、文件名和 redact；通过原生保存对话框选择路径。已有文件拒绝覆盖，失败清理临时文件；Windows/macOS 原生窗口尚未验收。 |
| `/retry` | 第二批已接入，原生待验收 | 显式输入该命令时重试上一条用户请求；由锁定 Gateway 检查附件可重放性并完成回退与重新提交，桌面通过可靠提示提交路径发送，完成后回读持久化历史。无会话或带参数时拒绝。 |
| `/undo` | 后续新增 | 先明确回退的是会话消息、待执行任务还是其他状态；显示预览与影响范围。不能把 CLI 的“回退并重新提问”简化为删一条界面消息。 |
| `/resume` | 第一批接入 | 按当前 Profile 的会话标识或名称定位、恢复；无参数时打开会话列表。处理重名、无结果和未服务 Profile。 |
| `/branch` | 已接入，原生待验收 | `/branch [标题]` 通过带修订与代次栅栏的 `session.mutate(branch)` 复制当前会话历史及工作区；成功后打开子会话。响应丢失时桌面进程内保留原请求重试，打开失败时给出子会话 ID 供 `/resume`。 |
| `/compress` | 第二批已接入，原生待验收 | 预览和实际压缩均沿可靠提示提交路径处理。隔离 Gateway 验证预览不改变历史，长会话实际压缩缩短持久化历史且原会话可恢复；原生窗口、失败与断连恢复仍待验收。 |
| `/rollback` | 后续新增，最后实施 | 文件检查点恢复必须列出目标文件、冲突与覆盖范围，保留用户手工修改；无可验证检查点或工作区所有权时拒绝。 |

## 4. 已开放命令的收紧范围

本节是实施前必须复核的现有入口，不能只处理上面的 51 个命令。以下是**拟议策略**，不是当前实现状态。

| 命令 | 拟议处理 | 审核重点 |
| --- | --- | --- |
| `/new`、`/sessions`、`/model` | 保留前端处理 | 继续拒绝当前未支持的参数；`/model` 打开设置不应被描述为立即切换当前会话模型。 |
| `/skills` | 只开放锁定 Gateway 的待审批查看与处理子命令 | 严格校验子命令；不能以命令族在允许集合中为由放行 `search/install/audit` 等 CLI hub 操作。 |
| `/yolo`、`/approvals off` | 从普通候选移除并在桌面执行入口拒绝；审批设置另行设计 | 当前允许集合含这些名称；需核对当前配置页能否准确显示并修改审批状态。 |
| `/debug` | 普通输入框不执行上传；诊断页可提供本地信息与独立的上传确认 | 锁定命令的说明是上传系统信息和日志。 |
| `/footer`、`/busy`、`/verbose`、`/platforms` | 逐项验证桌面效果；无效或语义不符则禁用 | 前端允许集合包含这些名称，上游命令元数据标记为 `desktop="terminal"`。 |
| `/voice` | 只保留与桌面语音能力一致的子命令 | 锁定 Gateway 已拒绝本地会话的 `/voice tts`；其他参数也须有可观察效果。 |
| `/usage`、`/suggestions`、`/memory`、`/kanban` | 按子命令区分读取与写入 | 锁定 Gateway 的判定按具体参数变化；候选可用性不能只按命令名。 |
| 插件命令、用户快捷命令、Skill | 保留动态目录，但以当前 Profile/会话为准 | 不能把动态名称绕过桌面策略；执行前核对类型、所属 Profile、会话与参数，错误时显示明确原因。 |

其他已开放命令按同一审查表逐个核对：是否在桌面有结果、是否涉及配置写入、是否允许运行中执行、是否依赖 CLI 交互。未核对的命令保持原状，不在第一批顺带改变行为。

## 5. 实施设计

### 5.1 一份桌面策略，三个入口使用

在聊天 feature 定义可测试的桌面命令策略：规范命令名与别名、参数形态、桌面动作、Gateway 转发资格、不可用原因。`commands.catalog` 只提供当前 Profile/会话的发现信息；桌面策略决定候选是否展示、是否可选，以及直接输入时如何处理。`@Skill`、插件命令和用户快捷命令采用各自的动态来源，不能无条件套用内置命令白名单。

目前 `CommandSuggestions` 会显示 `available=false` 的条目。本方案建议普通输入框默认只列可用命令；需要帮助时可显示“仅 CLI 可用/请在设置页操作”的说明，但不可点击执行。直接输入未知、禁用或参数不支持的命令，返回明确的桌面错误，不创建空会话，也不把文本误发给模型。

### 5.2 前端动作和宿主执行分开

- 纯导航与现有聊天状态操作留在 `apps/frontend/src/features/chat/`，复用现有控制器，不为跳转页面新增 Tauri 命令。
- 文件保存、剪贴板、外部路径、产品进程等原生能力经 `@hermess/contracts` 注入，由 `apps/desktop/src/adapter/` 与 Rust 所属模块实现。Windows 路径保持普通 Win32 写法；macOS 使用原有路径规则。
- 对确实需要 Gateway 的命令，Rust 执行入口再次检查桌面允许的命令与子命令，并核对固定 Profile 和会话归属。前端隐藏不是权限边界。Gateway 的权限与 `command_verdict` 是最后一道接收方边界，客户端不得假设其接受。
- 对执行后的 `exec`、`send`、`prefill`、拒绝、超时和断连分别处理。`send` 仅由客户端沿现有可靠提交路径提交一次；失败应保留用户输入并提供可恢复状态。
- 关键日志记录操作标识、命令名、Profile、会话、开始、Gateway 回执/拒绝及最终结果；不记录命令正文、消息内容、凭据或令牌。

### 5.3 范围与顺序

1. **第一批：目录准确性与现有能力映射。** 逐项核对已开放命令；统一前端候选和直接输入判定；宿主拒绝桌面禁止命令及不支持的子命令；接入 `/history`、`/resume`、有限语义的 `/stop`、`/config`、`/tools`、`/toolsets`、`/cron`、`/plugins`。若某条映射的实际语义无法与名称一致，该条保持禁用并在实现记录中说明。
2. **第二批：独立、可验收的新增功能。** 建议按 `/save`、`/retry`、`/compress` 的顺序分别实施。每项单独核对锁定 Gateway 协议、持久化和失败恢复；不把三个功能捆成一个不可拆的提交。
3. **第三批：后台任务与会话变更。** 在产品具备任务可视化、取消及重连恢复后，再评估 `/bg`、`/btw`、`/agents`、`/queue`、`/steer`；`/branch`、`/undo`、`/rollback` 需先证明数据所有权和恢复语义。

方案审核通过后才开始实现。若实施中证明某项必须修改锁定 Hermes fork，应先给出客户端无法适配的代码与协议证据、拟改范围和影响，另行取得明确审批；不能把本方案审核当作 fork 修改授权。

## 6. 验收标准

1. **目录与拦截：** 当前 Profile 和当前会话的可用候选准确；禁用命令通过点击、键盘选择、直接输入和直接调用宿主接口均无法执行；受支持命令的别名、参数与子命令一致。禁用输入不创建会话、不改变配置、不提交给模型。
2. **真实接收方：** 对每个新增或改变的 Gateway 调用，先核对生产请求形状、权限与返回值，再对锁定 Gateway 验证成功和关键拒绝路径。前端类型检查、字符串断言或模拟 Gateway 不作为接口验收。
3. **用户流程：** 检查新会话、已有会话、运行中、断连、重连、Profile 切换、工作区切换、失败重试、取消与恢复；确认错误能解释原因，操作不会误落到其他 Profile。
4. **平台：** Windows 和 macOS 分别验证原生窗口中的导航、文件对话框、剪贴板、路径及相关进程行为。单平台测试、构建或脚本通过不能写成双平台原生验收。
5. **回归与记录：** 验证 `/new`、`/sessions`、`/model`、Skill、插件命令、附件和普通消息提交；按实际改动运行前端类型检查、构建、契约/架构检查、Rust 格式/编译/定向测试及必要的 Gateway 验证。实施完成后更新 `ROADMAP.md`，区分已实现、已验证和未完成项。
