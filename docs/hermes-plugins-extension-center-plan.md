# 扩展中心接入 Hermes 插件：客户端与锁定 Agent 数据组装方案

状态：方案已部分实现，Windows 本地工程检查通过；原生页面操作与真实插件安装待用户测试，macOS 未验收。编写依据为 2026-10-29 的产品工作树和 `runtime/upstream.lock.json` 锁定的 Hermes fork 提交 `882037eb8745b505db438217513c4c94f95c93c1`。本文所说的“仓库数据”是锁定提交中的插件目录及契约，不等于用户机器上已经安装或启用插件。

## 当前实现（2026-10-29）

`scripts/generate-hermes-plugin-catalog.mjs` 从锁定 checkout 生成目录快照，`pnpm build` 自动执行一致性检查。扩展中心 `HermesPlugins.tsx` 只展示「插件源列表」；搜索输入实时筛选，按钮及回车也可提交搜索。点击安装后复用 Skill 的目标 Profile 列表，逐一读取已安装状态并安装到选中的 Profile；「专家管理 → 当前 Agent → 插件」展示已安装列表、加载状态和管理操作。Rust `runtime/hermes_plugins.rs` 从目标 Profile 的 Agent 安装元数据读取安装事实，默认 Profile 额外读 Gateway 加载状态，命名 Profile 尝试读插件 Hub 状态。命名 Profile 的原生 HTTP 票据在 Agent 中建立对应 home 的上下文，写入路由中的 `_config_profile_scope(None)` 使用该上下文，因此客户端允许对已服务的命名 Profile 安装和管理。更新新增能力时需再次确认。真实插件操作与双平台实机验收仍是未完成项。以下保留原方案及后续验收标准。

2026-10-29 试用反馈：安装后个人配置仍显示 0 个插件。开发版客户端日志记录 `dialog.message not allowed`，而三个 Profile 的插件目录均无新安装记录；安装流程在 Profile 选择后调用的 `window.confirm` 被桌面权限拦截，未发出安装请求。现将来源仓库、固定 SHA、能力与环境要求放进 Profile 选择弹窗，点确定后直接调用 Agent 安装接口；每个目标回读安装记录后才计为成功。个人配置中的卸载和更新能力确认也改为页面内确认，避免同一权限问题。此修复仍待用户重试真实下载。

2026-10-29 检索补充：`hermes-session-reset-policy` 已在锁定目录，源仓库为 `https://github.com/fastfinge/hermes-session-reset-policy`；原英文目录无法匹配中文“自动新对话”，输入 `session` 时该条目排在初始 40 项之外。客户端增加中文检索词，并优先展示名称命中项；卡片标题和说明保持目录原文，不展示专属中文补充。此条目只负责接入消息经过空闲或每日边界时开启新会话，安装后还需按 Agent 的 `session_reset` 配置启用策略。

## 目标与边界

在现有**扩展中心**增加「Hermes 插件」分类。分类显示的数据由两部分组装：

1. **Hermes Agent 锁定仓库**提供可发现的插件目录、固定提交、兼容条件、能力说明及移除清单。
2. **客户端连接的产品自有 Hermes 实例**提供当前 Profile 的实际安装、启用、加载和错误状态；客户端提供本地化文案、筛选和操作入口。

不另建市场服务，不从参考桌面项目复制代码或素材，不把 fork 的目录记录当作本机状态。所有读写限定在本产品自有的数据根、Gateway 和 Profile；不能扫描或接管用户已有的官方 Hermes 安装。首期只覆盖目录中的插件和产品实例内已安装插件；任意 Git URL 安装不进入首期。

## 页面结构

扩展中心顶层分类调整为：**专家｜技能｜Hermes 插件｜MCP**。原「技能 · 插件」改为「技能」，继续展示 Skill；现有 MCP 分类与「专家管理 → MCP」的职责保持原样。

扩展中心「Hermes 插件」页是**插件源列表**，不设置“可发现/已安装”切换。目录卡片展示名称、简介、仓库来源、分类、来源级别、维护者、目录版本与固定 SHA 短码、适用平台、兼容要求及能力摘要；点击安装后选择一个或多个已服务的 Profile，弹窗标明各 Profile 的已安装或状态不可用情况，不在源列表管理插件。

「专家管理 → 当前 Agent → 插件」负责已安装列表。这里区分“已安装未启用”“已启用且已加载”“加载失败”“状态未知”，提供当前 Agent 可用的启停、更新和卸载。已安装但不在当前锁定目录的插件也在此显示，标为“目录外安装”，不伪造其目录元数据；不要用“源列表里有”推断“已安装”。

用户选择 Profile 后，状态和操作只针对该 Profile。切换 Profile 或 Gateway 纪元时清除旧结果并重读；目录数据可以共用缓存，运行状态不能跨 Profile 共用。无 Gateway 时仍可看本地目录，但状态显示“未连接，无法核实”，安装和管理操作不可用。目录获取失败时明确标出“目录不可用”，不展示过期目录为当前目录。

## 数据契约与组装规则

建议在 `packages/contracts` 中定义客户端自己的 `PluginCatalogItem`、`PluginRuntimeState` 和 `PluginViewItem`，不要把上游 Python 返回的任意字段直接透传给页面。

| 字段组 | 权威来源 | 处理规则 |
| --- | --- | --- |
| `name`、`repo`、`sha`、`version`、`category`、`tier`、`platforms`、`requiresHermes`、`capabilities` | 锁定仓库目录 | 构建时从锁定提交生成 UTF-8 JSON，记录源提交与条目数；保留上游目录校验和移除规则。版本只是展示值，安装身份是目录名称加固定 SHA。 |
| `installed`、`enabled`、`loaded`、`error`、`installedSha` | 当前产品实例及指定 Profile | 由宿主读取并归一化；读取失败保留 unknown，不能默认为 false。运行中 `plugins.list` 只证明加载状态，安装记录须另取本机状态。 |
| `displayName`、中文说明、筛选词、按钮与提示 | 客户端 | 缺少翻译时显示上游原文；不改写目录的技术字段。 |

合并时优先用上游安装 sidecar 的 `catalog_name` 匹配目录名称；名称相近、显示名相同或仓库 URL 相同都不能单独作为“已安装”的证明。对目录外安装项使用上游返回的稳定 registry key。目录 `removed.yaml` 命中的条目不能提供安装或更新按钮，并显示上游给出的移除原因。目录 `platforms` 与当前 Windows/macOS 不匹配时可展示详情，但禁用安装并解释原因。所有目录文案都是数据，不作为执行指令。

## 客户端与 Agent 的职责

1. **构建期**：从 `runtime/upstream.lock.json` 读取锁定 SHA，校验当前 `upstream/hermes-agent` HEAD 一致；调用锁定仓库的目录解析/校验代码生成产品只读快照。产物记录 `sourceCommit`、生成工具版本和校验结果。打包时检查快照与 payload 同一锁定提交；不能从开发机随意目录生成发行数据。
2. **Rust 宿主只读适配**：按 `ResolvedProfileScope` 定位产品自有 Gateway；读取当前 Profile 的插件加载状态，另核对产品实例的安装记录。统一返回规范化状态、来源及错误，不把密钥、绝对路径或原始配置送到前端。
3. **前端组装**：用目录快照和状态按稳定键合并，按 Profile 与 Gateway 纪元缓存状态；实现搜索、筛选、详情及状态提示。目录来源和运行状态在 UI 上分别标明。
4. **写操作适配**：先做接口探针，证明锁定 Gateway 的 Dashboard 插件路由或其它受支持入口可按 Profile 安全操作，再固定为宿主白名单。安装只接受目录名称和当前快照 SHA；执行前由宿主重新读取目录/移除清单与实际状态，拒绝过时卡片。若该路由在产品形态不可用，再设计由共享进程管理器托管的产品自有短时 helper；不得把 TUI Gateway 的 `plugins.manage` 当作已存在的产品 RPC，也不得让前端执行任意命令。
5. **操作结果**：安装、启停、更新、卸载各自回读本机安装与运行状态；显示“已安装但未加载”“待重启/待新会话生效”等真实状态。需要依赖、权限、能力变更或扫描确认时，展示上游返回的具体条件后再继续；失败不伪装成成功。卸载只作用于产品实例内由此流程管理的用户插件。

安装与更新可能访问插件仓库并创建子进程。若使用 helper，必须接入共享进程管理器，覆盖子进程树、超时、失败和托盘退出；Windows 后台运行不弹出终端窗口，macOS 使用同一产品数据根与进程清理边界。任何秘密配置只在宿主与 Agent 之间处理，不回显给 WebView。

## 建议实施顺序

1. **只读交付**：目录快照生成与校验、插件分类、当前 Profile 已安装/启用/加载状态。用 `hermes-session-reset-policy` 验证“目录可见但未安装”的显示。
2. **目录内安装**：完成产品 Gateway 路由探针、固定 SHA 与移除清单复核、安装结果回读、必要的能力确认；确认失败时不写入。
3. **管理操作**：启停、更新、卸载和插件设置；逐项验证 Profile 作用域、并发冲突、插件生效时机与回滚/重试提示。

这三个阶段是实施顺序，不表示任一阶段已经交付。若锁定版本的产品 Gateway 缺少必要写入入口，先交付只读阶段，并把客户端适配证据与所需范围列出；不得为赶进度直接修改 Hermes fork。

## 验收标准

- **数据来源**：生成快照的 SHA 与锁文件及打包的 Agent 源码一致；目录条目数、固定 SHA、移除项与上游解析结果一致。断网时仅使用可追溯快照。
- **状态准确**：未安装、已安装未启用、启用但加载失败、目录外安装和无法核实分别显示；切换 Profile、Gateway 重连与重启后不沿用旧状态。
- **隔离**：在 Windows 和 macOS 分别验证产品实例与现有官方 Hermes 并行；安装、启停、卸载、退出均不影响官方实例或别的 Profile。失败和超时后没有残留产品 helper 或子进程。
- **实际操作**：目录内插件安装、启停、更新、卸载逐项回读；以会话重置插件验证启用后对下一条渠道消息的预期影响，同时验证未启用时长时间空闲不会由核心自动轮换。这里只能在真实渠道与原生客户端操作后记为实机验收。
- **工程检查**：按改动运行目录生成/锁定校验、契约与架构检查、前端类型检查及构建、Rust 格式/编译/定向测试、产品 Gateway 冒烟；记录 Windows 与 macOS 各自实际执行结果及未验收项。

## 主要待核实项

1. 当前产品 core payload 是否包含目录解析与 Dashboard 插件管理所需的完整文件、依赖及 HTTP 路由；源码存在不代表打包后可用。
2. Dashboard 插件路由在单 Gateway 多 Profile 下的作用域和鉴权，以及安装时的响应、超时、能力确认和后台任务语义。
3. 锁定目录的在线刷新和移除清单与产品固定快照的冲突策略；首期统一使用锁定快照，在线目录不参与安装决策。
4. 插件修改后的即时加载、需新会话生效和需重启三种情况如何从 Agent 返回值可靠区分。

以上待核实项是实现前的证据门槛，不是对当前客户端能力的承诺。
